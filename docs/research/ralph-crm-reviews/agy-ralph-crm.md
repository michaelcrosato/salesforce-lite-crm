- **Source repo:** `C:\dev\agy-ralph-crm` (reviewed via detached worktree of the snapshot tag)
- **GitHub remote:** https://github.com/michaelcrosato/agy-ralph-crm
- **Snapshot tag:** `pre-purge-20260609`

- **History reviewed:** 491 commits (2026-05-28 → 2026-06-09), full `plan/`, `.ralph/`, `tickets/`, journal, and source

## Verdict

This is the most operationally mature of the ralph-crm attempts in harness design: its layered verify-rollback AFK loop (`run-afk-loop.ps1`), evidence-driven journal discipline (94 cycles with exact commands and exit codes), and the `plan/ROADMAP.md` modernization audit are the highest-value artifacts. The CRM itself is astonishingly broad (105 tenant-scoped tables, 222 feature specs, marketing-sequence engine rivaling a real MAP) and genuinely test-covered (~550-569 Vitest tests parameterized over mock and real-Postgres backends), but it is mock-first persistence with Postgres retrofitted, has near-zero real UI depth, was never deployed, and its CI never ran remotely (the loop was forbidden to push; at one point `main` was 115 commits ahead of origin). The repo's clearest lesson is double-edged: hard quality gates kept 491 commits green with zero reverts, but once the safe product backlog drained, the loop spent ~35 of its 94 cycles on a self-generated 400-line-budget/`any`-cast compliance treadmill. Salvage the harness patterns, the tenant-isolation stack, the competitive audit, and the domain catalog; do not salvage the code wholesale.

## Product & Domain Design

**Scope.** Five declared lanes (root `GOAL.md` §4): Sales CRM, Marketing CRM, Service CRM, Metadata CRM ("custom fields/objects without tenant-specific SQL migrations"), and "Agentic Engineering" (the harness itself as a product lane — a framing worth keeping).

**Entity model.** Core relational spine (`GOAL.md` §9): `organizations, users, roles, memberships, accounts, contacts, leads, opportunities, activities, activity_links, audit_logs, field_definitions, layout_definitions, validation_rules, picklist_dependencies, custom_entity_types, custom_entity_records`. Extended surfaces add campaigns/members/influence, products/pricebooks/opportunity-products/product-schedules, contracts/subscriptions/invoices, quotas/commissions/territories/forecasts, tickets/macros/escalations/SLA, email trackers + open/click/reply/bounce/read-time event tables, the entire marketing-sequence family, webhooks/outbox, reports, documents, embeddings. Final schema: **121 `pgTable` definitions across 10 domain files** (`packages/db/src/schema/{common,communication,crm,custom,documents,marketing,platform,sales,sequences,service}.ts`), 105 of them tenant-scoped.

**Multi-tenancy: RLS + app-level dual enforcement.** This is the repo's strongest domain decision and is fully implemented:
- `packages/db/src/_tenant.ts`: `withTenant(orgId, db, run)` wraps a transaction in `AsyncLocalStorage` and issues `SELECT set_config('app.current_org_id', $orgId, true)` (or `SET LOCAL` on mock); `getActiveOrgId()` throws `"RLS Isolation Violation: Tenant context not set."` if unset.
- `packages/db/drizzle/0001_enable_rls.sql`: **105 `ENABLE ROW LEVEL SECURITY` + 105 `CREATE POLICY "tenant_isolation" ... USING ("org_id" = current_setting('app.current_org_id', true))`** — auto-generated by `scratch/generate-rls.js`, which parses the base migration for tables containing `org_id`. That generator is a reusable trick.
- App-level backstop: `assertTenantOwns(entity)`, `tenantAuth` middleware, and a generic `createPgStore()` factory (`packages/db/src/stores/pg-factory.ts`) that injects `eq(table.orgId, getActiveOrgId())` into every query when the table has an `orgId` column.
- Mandated test shape (`GOAL.md` §10.3): every feature requires positive tenant tests **and negative cross-tenant tests**; "aggregations are especially risky."

**Custom objects (metadata-over-fork).** `defineObject()` SDK in `packages/metadata` — 8 field types (`string, number, boolean, date, lookup, picklist, multi_picklist, rich_text`), per-tenant registry, runtime-compiled Zod validation, storage in shared `custom_entity_types`/`custom_entity_records` JSONB tables, REST CRUD at `/api/custom/:typeName`, **dynamically generated MCP tools** (`crm_create_<obj>`, `crm_list_<obj>`, …), referential-integrity validation of lookups under tenant context (spec 143), and a centralized `PicklistRegistry` shared between standard and custom fields (spec 144). This was explicitly modeled on Twenty's "killer feature."

**Customization hierarchy** (`GOAL.md` §5, verbatim ladder worth carrying forward): tenant config → metadata/custom objects → first-party module → isolated customer module → fork "as a last resort; must not mutate shared core for a single tenant."

**Marketing sequence engine** is the deepest single subsystem — `.ralph/specs/0177-0222` are 45+ consecutive specs covering steps (email/task/sms/call/webhook), A/B split with automatic winner promotion, branching, exit triggers, goal conversions, suppressions/exclusions, sending windows + timezone delivery, per-sequence daily limits, domain throttling, recipient frequency caps, dynamic sender assignment, email threading, engagement scoring, and (final feature, spec 147) event-driven step delays ("wait until open/click or X hours").

## Architecture

**Layout:** pnpm workspace + Turborepo over `apps/{api,web}`, 16 `packages/*` (`core, db, api-client, auth, audit, metadata, workflow, reporting, forecasting, webhooks, documents, search, mcp, observability, ui, testing`), `modules/{service-lite,_template}`.

**Stack (with stated rationale in `plan/ROADMAP.md`):** Node `>=22.22.3 <23` (pinned to Jan/Mar 2026 CVE floor), pnpm 11.1.2 via corepack, Hono + `@hono/zod-openapi` (auto OpenAPI at `/openapi.json`, Scalar docs at `/docs`), typed Hono RPC client package consumed by Next.js 16.2.6 / React 19 (Turbopack + React Compiler), Drizzle 0.45.2 (upgrade pulled forward to clear GHSA-gpj5-g38j-94v9 SQL-injection advisory), Zod, Biome 2.4, Vitest 3.2, Playwright 1.60, pino bridged to OTel, `@modelcontextprotocol/sdk`, uuid v7 (replaced 111 `Math.random()` ID sites).

**Boundary rules** (root `AGENTS.md`, enforced in review not tooling): `packages/core` must never import `apps/*`/`modules/*`/customer code; business logic lives in packages, never Next.js handlers; `packages/webhooks` stays outbox/simulation-backed; modules are isolated seams. Dependency direction diagram in `GOAL.md` §6.1.

**Persistence strategy — the big caveat:** the runtime default is `DB_DRIVER=mock`, an in-memory store (118 per-aggregate store files under `packages/db/src/stores/`) kept schema-parallel with Drizzle. Real Postgres is a parallel path: `createDbClient()` (node-postgres pool), 8 migrations, testcontainers (`pgvector/pgvector:pg15`) gated by `isDockerAvailable()` in `packages/testing/src/pg-container.ts`, with tests parameterized to run against **both** backends. This dual-backend parameterization is a genuinely reusable pattern (fast mock loop + truthful PG verification), but it also means the "production" path was only ever exercised inside testcontainers.

**Other notable implemented patterns:**
- Append-only audit with SHA-256 hash chain + Merkle-tree WORM export and verifier (`packages/db/src/stores/audit-hash.ts`, `scripts/agent/verify-audit-integrity.mjs`).
- Hybrid search: trigram + Levenshtein lexical, pgvector embeddings (1536-dim, HNSW), Reciprocal Rank Fusion, plus a cross-encoder reranker seam; deterministic mock embedding provider (token-vector sums) so semantic tests pass offline.
- Bitmask RBAC middleware layered onto `tenantAuth`.
- Migration conflict-prevention gate (`scripts/agent/check-migrations.mjs`: index continuity, journal-tag existence, prefix uniqueness) hooked into `agent:doctor`.
- AI surfaces (attribute-enrichment worker, conversational BANT lead-qualification bot) all behind mock providers with explicit `ALLOW_LIVE_AI_PROVIDERS` opt-in (spec 111) — `.env.example` is a documented mock-safe operator contract (`EMBEDDINGS_PROVIDER=mock`, `RERANK_PROVIDER=mock`, `OTEL_DISABLED=1`).

## Implementation Reality

Journal records test growth 403 → 569 (May 29-31) with per-cycle exact counts; final recorded green run 550/550 across 172-176 files (count fluctuates because PG-backend variants skip without Docker). **Thin or hollow:** `apps/web` is a dashboard shell (5 routes: home, accounts, leads, opportunities, territories) with a "glassmorphism" aesthetic spec (0117); no auth UI, no sequence/ticket/report UIs. `bench/` contains only `budget.json` (`queryTimeMsLimit: 50`, `leadConversionTimeMsLimit: 100`) — **no benchmark was ever run**; performance targets are unmeasured. `test-results/` empty. The README's "All 81 tickets completed" and "559 tests" are slightly stale vs. last verified runs.

**Honesty self-correction:** root `GOAL.md` §2 ("Evidence and Truth Policy") explicitly lists earlier doc claims that were *not real* — `apps/worker`, `bench/` as active topology, Auth.js, Tailwind/shadcn, BullMQ/Redis, `pnpm check:boundaries` — "evidence to reconcile, not instructions to copy." This is documentary proof that earlier loop docs hallucinated features and a later audit had to disclaim them. The section format (adopted / not-adopted-as-fact / conflict-resolution) is worth copying into any agent-maintained architecture doc.

**Commit-type mix (491 commits):** ~225 feat, ~140 docs, ~100 refactor/chore/test, ~25 fix, **0 reverts** — because the loop rolled back failures *before* commit (`git reset --hard`), history stayed clean. Churn: +308,168 / −75,125 lines (~24% of written lines later deleted, mostly the monolith decompositions).

## Autonomous-Harness Learnings (highest value)

**Identity:** "agy" = Google **Antigravity CLI** (journal Cycle 147 cites "Gemini 3.5 Flash… thinkingLevel.HIGH… evaluator-optimizer contracts"). At least three different agent systems touched the repo: the Antigravity loop, a "Principal SWE Agent (Opus 4.7, 1M ctx)" that wrote the `plan/` modernization blueprint, and `google-labs-jules[bot]` (one UI commit, with a learning memo in `.Jules/palette.md`). Root docs + `plan/` docs are two parallel governance layers from different agents — they drifted (see Pitfalls).

**The loop (`run-afk-loop.ps1`, 279 lines — the single most reusable file):**
1. **Idle scan:** regex-scan `tickets/TICKET*.md` for non-completed/non-blocked; if none → write `idle` heartbeat, sleep 60s (originally exited; `ba83e24` made it perpetual).
2. **Retry ledger:** `afk_state.json` per-ticket `{attempts, lastAttempt, lastError}`; **3 failed attempts → ticket auto-rewritten to `Status: blocked`** with an appended "Blocked Notes" section naming the loop and timestamp.
3. **Feed-forward:** previous failure text is injected into the next prompt: `"[CRITICAL NOTE] On the previous attempt, this task failed during validation with: <err>. Ensure you do NOT repeat the same approach."`
4. **Dirty-workspace abort:** `git status --porcelain` non-empty before run → hard stop ("protect user-owned changes").
5. **Pre-flight gates:** `pnpm verify` + `pnpm test` must pass *before* the agent runs (never start from red).
6. **Agent call:** `agy --dangerously-skip-permissions --print-timeout 15m --print <generic prompt: read highest-priority ticket, follow AGENTS.md, implement atomically, verify, update ticket, stop>`.
7. **Post-flight, two tiers:** targeted (Biome on changed files + `vitest run --related <changed>`) then comprehensive (`verify` + `test`). Any failure → `git reset --hard HEAD && git clean -fd`, record `lastError`, continue.
8. **Heartbeat telemetry:** `afk_heartbeat.json` rewritten at each state with `{lastHeartbeat, status, pid, runCount, currentTicket}`; observed statuses: `scanning/idle/running/blocked/dirty_workspace/preflight_verify_failed/preflight_test_failed/agent_failed/targeted_verify_failed/comprehensive_verify_failed/success`. Final snapshot: `runCount: 37, status: idle`.

**Governance documents:** layered read-first order (`AGENTS.md` → `plan/GOAL.md` → root `GOAL.md` → `plan/ROADMAP.md` → `docs/ai/REPO_MAP.md` → `plan/PROGRESS.md` → lowest unblocked ticket → matching spec). `ralph.yml` budgets: `max_context_tokens: 32768`, `max_file_lines_standard: 400`, allowlisted commands. `.aiignore` excludes logs/dist/scratch "to maximize token efficiency." `CLAUDE.md`/`.cursorrules` are deliberate thin pointers to one canonical `AGENTS.md` — good multi-tool hygiene.

**The Honesty Protocol** (`plan/AGENTS.md` §7, quote): *"Never claim a check passed unless its command actually ran and exited 0 in your transcript. Record absent gates as 'not found'… When in doubt, open a follow-up spec rather than fold work into the current one."* Combined with the journal format (every cycle: Baseline → Research Refresh → Action Plan → Verification Log with exact commands/exit codes/test counts), this produced auditably truthful records — and the verification logs *do* record failures honestly (e.g., Cycle 77: "first broad gate exit 1… isolated rerun exit 0, did not reproduce").

**How the loop actually behaved:** 101 commits on 05-28 (scaffold + feature blitz, specs 0100-0222), 81 on 05-29 (audit + Phase 0 modernization), 193 on 05-30 (peak: real PG, RLS, OTel, MCP, custom objects, pgvector), 110 on 05-31 (hardening + the compliance treadmill), then a 7-day silence, then 6 commits on 06-08/09 (one feature, one real race-condition fix, loop hardening). Cadence pattern: `feat` commit followed by `docs:` progress/journal commit — a two-commit-per-cycle rhythm that makes history legible. Backlog replenishment was itself a loop activity ("Cycle 90 — Knowledge Compaction & Backlog Promotion": archive completed items, formulate next wave).

## Observability Stack

Two **separate** layers — an important distinction for the successor harness:

1. **App observability (CRM product):** `docker-compose.yaml` runs `otel/opentelemetry-collector-contrib` (OTLP gRPC 4317 / HTTP 4318; batch processor `timeout: 1s, send_batch_size: 256`; traces → Jaeger, metrics → Prometheus exporter `:8889`, namespace `crm`), Prometheus (5s scrape), Jaeger all-in-one (UI 16686), Grafana on **3010** ("to prevent colliding with Next.js on 3000"), anonymous-admin, auto-provisioned datasources and a default dashboard. `grafana/dashboards/crm-dashboard.json` panels: API request rate `sum(rate(http_server_duration_count[1m])) by (http_route)`, average latency (`_sum/_count`), Node heap/external memory. Plus an in-process `MemoryTelemetry` class (`packages/observability/src/memory.ts`): `perf_hooks.monitorEventLoopDelay` + rolling 5-sample `heapUsed` history with monotonic-growth leak detection, wrapped around sequence-execution loop iterations. Default-off (`OTEL_DISABLED=1`) for unattended loops.
2. **Loop observability (harness):** *not* Grafana — just `afk_heartbeat.json` (machine-readable state), `afk_monitor.log` (timestamped narration), `afk_error.log` (failures), `afk_state.json` (retry ledger). It works, but nothing ever graphed loop health. **Reusable idea for the new orchestrator:** the heartbeat state machine is exactly the event stream you'd want exported as OTel metrics into the same Grafana the repo already ships — the two halves were never connected here.

## Pitfalls & Anti-Patterns Observed

1. **The line-budget treadmill.** Specs 075-141 (~35 cycles, May 31) were almost entirely file-splitting and `any`-cast removal generated *by the loop's own 400-line rule* — including splitting *test files* (specs 098-109) for budget compliance. Burn-down had value (Biome warnings 42→0, real type bugs found), but it crowded out product work for a full day of the four-day run. Root `AGENTS.md` later added the corrective: "Large files above the 400-line budget are **not automatically work items**. Split only by real responsibility and active spec." Put that sentence in the successor harness from day one.
2. **Tests bent to pass a security change.** Cycle 15: deep RBAC broke legacy tests; the fix was elevating test fixtures' `permissionsMask` from 7→63 (full admin) across 7 suites — adapting tests to the gate rather than auditing least-privilege. Honestly documented, but the pattern (agent weakens the assertion side) is exactly what a harness must flag.
3. **Shared-testcontainer races → global sequential testing.** One global PG container + per-suite `dbStore.clear()` truncation caused flaky cross-suite wipes; the fix was `--no-file-parallelism` (whole suite sequential) instead of per-suite schemas/databases. Slow-and-stable beat correct isolation; the successor should use per-worker databases.
4. **Doc duplication and drift.** Root `GOAL.md`/`ROADMAP.md`/`AGENTS.md` vs `plan/GOAL.md`/`plan/ROADMAP.md`/`plan/AGENTS.md` — two agents' governance layers, partially contradictory (root ROADMAP says "production-ready"; plan ROADMAP says "not ready for blind perpetual execution"). README test counts stale vs journal. One canonical doc set, machine-checked, is the lesson.
5. **Hallucinated-then-disclaimed features.** `GOAL.md` §2.2's list of things "not adopted as current fact" is a fossil record of earlier doc inflation (bench/, Auth.js, Tailwind, BullMQ, `quotes-lite`…). Agent-written docs need the same verification gates as code.
6. **Research-refresh ritualization.** Cycles 45-63's "Research Refresh" sections degrade into near-identical boilerplate (same Next.js CVE-2025-66478 and Node 22.22.3 links pasted 15+ times) — a mandated step performed as ritual compliance. Mandate research per *new spec family*, not per cycle.
7. **Never pushed, CI never proven.** No-push safety rule + no human merge step meant "main ahead of origin by 115 local commits" and a CI badge that never reflected a real run. A safe push/PR lane is a harness requirement, not a nice-to-have.
8. **Benchmarks declared, never executed.** `bench/budget.json` perf targets (50ms query / 100ms lead conversion) have no measurement anywhere. Don't carry numeric targets without a runner.
9. **Loop ended idle-spinning.** Final commits flipped zero-waste exit to "run loop perpetually on idle" (60s polls forever) — heartbeat shows it died idle at runCount 37. Perpetual idle without a replenishment trigger is wasted compute; pair idle detection with an explicit backlog-replenishment or shutdown policy.
10. **Mock-first persistence as default.** The in-memory store enabled the test blitz but doubled every store (118 mock files + PG factory) and left "production PostgreSQL RLS parity" permanently on the roadmap. If rebuilding: start PG-real (PGlite/testcontainers), generate the mock only if speed demands it.
